## 1. Objective and scope

本阶段在既有安全与耐久模块上装配单一 PydanticAI Agent，提供窄工具、受控本地 Skill、
checkpoint/compaction、结构化最终输出和可选 FTS5/BM25 历史检索。本次复验不新增第二套
Agent loop，不访问云模型真实账号，也不把摘要当事实源；使用确定性 fake ModelGateway 完成
模型调用、工具循环、预算耗尽和恢复证据，并携带已完成的真实 OpenSandbox/AnalysisRuntime
前置 Gate。

## 2. Detailed changes

本次没有修改 Phase 08 的 Agent 业务实现；解除阻塞依赖的实现变化位于
`src/dataharness/providers/durable/executor.py`，由 Phase 07 报告记录。复验确认以下既有
文件和行为继续有效：

- `src/dataharness/agent/assembly.py`、`model.py`、`tools.py`、`models.py`、`runner.py`：
  单一 PydanticAI Agent、ModelGateway FunctionModel、窄工具、UsageLimits 和结构化输出。
- `src/dataharness/agent/context.py`：目标/计划/进度、固定 Snapshot、FileVersion、领域
  引用、未解决问题和 PydanticAI message checkpoint；compaction 摘要经 ModelGateway。
- `src/dataharness/skills/registry.py`、`errors.py`：预装 Skill 的渐进发现、激活 hash、
  路径边界、只读语义和运行中修改拒绝。
- `src/dataharness/capabilities/memory/history.py` 与
  `src/dataharness/providers/memory/sqlite.py`：独立 SQLite FTS5/BM25 历史能力，不复制
  ProjectCorpus 索引、不引入向量数据库。
- `tests/integration/test_agent_phase08.py`：复验 Skill hash 变化拒绝、compaction 引用
  恢复、脱敏历史、Gateway 工具循环、结构化结果和预算耗尽 checkpoint。

## 3. Interface and invariant changes

None。既有接口与不变量在本次复验中保持：所有模型请求（包括 compaction/summary）经过
`ModelGateway`；Agent 只注册固定窄工具和显式激活 Skill；Skill 修改导致旧 Run 拒绝继续；
最终输出仅允许 `COMPLETED`/`WAITING`，引用字段必须使用稳定 `ResourceRef`；Project 跨文件
检索继续归属 ProjectCorpus，MemoryCapability 只查询对话历史。

## 4. Storage and migration impact

None。Phase 08 不新增 Runtime SQLite migration。checkpoint 文件继续保存在受控 Workspace
`tasks/<task>/state/checkpoints/`，Runtime SQLite 只记录序列、hash、Run/Snapshot 和定位元数据；
历史检索使用独立 SQLite FTS5 表。

## 5. Security and privacy impact

- 模型文本、工具返回值、历史写入和 checkpoint compaction 都经过 ModelGateway 的脱敏边界；
  测试确认邮箱不会原样写入历史。
- Agent 不可见 Host 路径、Runtime/Privacy SQLite 或任意 Python 执行接口；`execute_python`、
  `execute_sql` 和 Skill 脚本统一委托 `AnalysisRuntime`，真实执行由已认证 OpenSandbox 承担。
- Skill 只来自管理员预装本地目录；激活前只显示描述/hash，激活后重新校验内容 hash，路径
  越界、符号链接逃逸、超限和运行中修改均拒绝。
- 没有 CodeMode/Monty、在线 Skill registry、运行时安装包、Host shell 或真实云凭据。

## 6. Dependency changes

None。本次复验不改变 Phase 08 已锁定的 `pydantic-ai>=2.29.0` 与 `uv.lock`；依赖锁、
License/SBOM 和镜像漏洞证据沿用 Phase 05/06，未伪造新发布证据。

## 8. Exit Gate evidence

1. **所有模型调用包括 compaction/summary 均经过 ModelGateway。**
   `test_agent_tool_loop_and_structured_output_use_gateway` 断言工具循环两次请求都到达
   fake Provider；`test_checkpoint_compaction_preserves_domain_refs_and_restores_messages`
   断言 compaction 使用相同 Gateway 并保存新 checkpoint。
2. **Agent 只能看到已注册的窄工具和已激活 Skill。** Agent factory 只注册固定工具；
   SkillRegistry 未激活时只返回 descriptor，激活后才可读取脚本；工具循环测试通过。
3. **Skill 运行期间被修改时拒绝继续或要求新 Run。**
   `test_skill_registry_is_progressive_and_rejects_changes` 修改 `SKILL.md` 后得到
   `SkillChangedError`，旧 hash 不会继续执行。
4. **Compaction 后恢复仍引用正确 Dataset/Artifact/Finding，不把摘要当事实源。**
   checkpoint 测试恢复原 `ResourceRef`、Snapshot 和未解决问题，summary 单独保存，未被转成
   事实引用。
5. **Project 跨文件检索属于 ProjectCorpus；MemoryCapability 不复制项目索引或引入向量记忆。**
   Agent 的 `search_project` 只调用 AnalysisRuntime；独立 FTS5 历史测试验证 MemoryCapability
   使用自己的 HistoryStore，且不保留原始邮箱。
6. **不存在 CodeMode/Monty、在线 Skill registry 或运行时依赖安装。**
   Agent assembly 只使用 PydanticAI 原生工具、管理员本地 SkillRegistry、既有
   AnalysisRuntime/OpenSandbox；依赖方向检查与完整静态回归通过。
