## 3. Interface and invariant changes

- `create_agent(...)` 是 Agent 装配入口；返回的 Agent 只有项目文件列表/检索/检查、Python/SQL、输出检查、Finding 提交，以及存在时的 Skill 脚本和历史检索工具。
- `AgentDependencies` 固定 Task/Run/Snapshot、AnalysisRuntime、SkillRegistry、ContextCheckpointManager、ModelGateway 和可选 MemoryCapability，禁止把主机路径或第三方 Provider 暴露给模型。
- `AgentFinalOutput` 只接受 `COMPLETED`/`WAITING`，并要求回答、稳定 `ResourceRef` 和未解决问题；摘要字段不参与事实引用。
- `ContextCheckpointManager` 先原子写 Workspace checkpoint，再登记 `CheckpointMetadata`；恢复时必须校验 Run、Snapshot、序列、文件哈希和消息 JSON。
- `SkillRegistry` 在每次激活脚本前重新计算 `SKILL.md` 哈希；Skill 变化会抛出 `SkillChangedError`，要求创建新 Run。
- `HistoryStore` 只提供历史文本与来源引用的 `add/search` 协议；Project 跨文件事实仍由 `AnalysisRuntime.search_project` 委托 `ProjectCorpus` 提供。

## 4. Storage and migration impact

没有新增 Runtime SQLite schema migration。每个 checkpoint 使用独立的 `checkpoint-<sequence>.json` 文件，Runtime SQLite 只登记已有 `checkpoint_metadata` 元数据和内容哈希，避免覆盖旧恢复点。

历史检索使用单独配置的 SQLite 文件，包含 `history_entries` 和 `history_fts` FTS5 表；它不读取 ProjectCorpus 的索引文件。Workspace 新增的 checkpoint 目录受既有路径规范化、符号链接拒绝、原子写入和读取大小上限保护。

## 5. Security and privacy impact

- 所有模型请求由 `gateway_function_model` 调用 `ModelGateway.complete`；compaction/summary 同样走该入口。工具返回值、历史写入和 checkpoint 载荷分别经过 `sanitize_tool_result` 或 `sanitize_compaction`。
- Agent 不获得 Host 路径、Runtime/Privacy SQLite 连接、Workspace 对象或任意 Python 执行接口。Skill 脚本只由 `AnalysisRuntime.execute_python` 下沉到既有 Sandbox seam。
- Skill 根目录、Skill 文件、脚本目录和脚本文件均拒绝符号链接与越界路径；Skill 与脚本大小均有上限。
- 测试仅使用合成邮箱 `alice@example.test`，验证原始邮箱不会进入历史存储；没有使用真实 secret、生产数据或云账号。
