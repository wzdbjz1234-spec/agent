Lesson 13 · 把前 12 课串起来

端到端实操：跑通一次完整分析

本课带你把整个系统跑起来：启动 → 建项目 → 导文件 → 建任务 → 看事件流 → 读答案。每一步都告诉你「刚刚发生了什么、对应哪一课的哪个模块」。

0. 准备

前置条件（README.md:62-67）：Python、uv、Docker Desktop。依赖安装：

uv sync --locked
Copy-Item .\dataharness.example.toml .\dataharness.local.toml   # 若还没有本地配置

验证环境：

uv run dataharness --version
uv run dataharness check --config .\dataharness.local.toml
关于模型 Key 的诚实说明

没有真实 API Key 时，dataharness run 会 fail closed 拒绝启动（README.md:416-418）。 本课的主线流程（建项目/导文件/建快照/建任务/看事件）用 dataharness serve + 一个不执行模型调用的方式也能验证 —— 我们会明确标注每一步是否依赖真实模型。想看到 Agent 真实工作，请在 dataharness.local.toml 的 [model].api_key 填入你的 Key（README.md:328-347）。

1. 启动 API

单独启动 API（不需要 Docker）：

uv run dataharness serve --config .\dataharness.local.toml --host 127.0.0.1 --port 8000

健康检查（README.md:228-234）：

Invoke-RestMethod http://127.0.0.1:8000/healthz     # {"status":"ok"}
Invoke-RestMethod http://127.0.0.1:8000/readyz      # {"status":"ready"}

对应的代码在第 03 课读过：api/app.py:134-141。打开 http://127.0.0.1:8000/docs 能看到全部接口（Swagger UI）。

2. 创建 Project 并导入文件

$project = Invoke-RestMethod -Method Post -Uri http://127.0.0.1:8000/projects `
  -ContentType application/json -Body '{"name":"demo-project"}'
$projectId = $project.id

这走的是 POST /projects → corpus.create_project（第 03/07 课）。造一个 CSV 并上传：

@("id,name,amount", "1,alpha,100", "2,beta,250", "3,gamma,80") | Set-Content -Path .\demo.csv -Encoding utf8
curl.exe -X POST "http://127.0.0.1:8000/projects/$projectId/files" `
  -H "X-File-Name: demo.csv" -H "Content-Type: application/octet-stream" --data-binary "@demo.csv"

看文件状态（应该是 READY）：

Invoke-RestMethod "http://127.0.0.1:8000/projects/$projectId/files"

刚才发生的事（第 07 课）：文件名规范化 → 原件存入 runtime-data/projects/{id}/sources/ → 魔数识别 CSV → 提取 → FTS5 索引 → 版本标记 READY。你可以去目录里看看那三个产物。

3. 创建 Snapshot

V1 API 没有快照路由，用 Python 直接调服务（README.md:292-295）：

$snapshotId = uv run python -c "from pathlib import Path; from dataharness.api import ApiService; from dataharness.config import load_settings; from dataharness.domain import ProjectId; s=ApiService.from_settings(load_settings(Path('dataharness.local.toml'))); print(s.corpus.create_snapshot(ProjectId('$projectId')).id)"

这就是第 07 课的不可变快照：固定了当前所有文件的版本。从此这个 Run 的输入视图不会变。

4. 创建 Task

$taskBody = @{ project_snapshot_id = $snapshotId; prompt = "分析 demo.csv 中金额的平均值" } | ConvertTo-Json
$task = Invoke-RestMethod -Method Post -Uri "http://127.0.0.1:8000/projects/$projectId/tasks" `
  -ContentType application/json -Body $taskBody
$taskId = $task.task.id

任务创建时同时创建了 Run（响应里能看见 run.id）。Task 进入 QUEUED —— 等待 Worker 领取。

注意

只启动 serve 时没有 Worker，Task 会一直 QUEUED —— 这是设计：API 不执行任务（第 11 课「API 进程不持有 Worker」）。 要让任务真正跑起来，要么启动 dataharness worker（需要沙箱和模型 Key），要么用 dataharness run 一键启动全家桶（第 5 节）。

5. 一键启动全家桶（真实链路）

准备好 Docker Desktop、模型 Key、沙箱镜像后：

uv run dataharness run

它会（launcher.py:245-339，第 01 课提过）：依次启动 OpenSandbox（8080）→ API（8000）→ Worker，并在前台转发日志（前缀 [sandbox]/[api]/[worker]）。

现在重新创建 Task（或刚才的 Task 会被新 Worker 领取）。Worker 日志里的 [agent] 记录模型的有界思考、工具调用与结果摘要（README.md:411-413）。

观察事件流（SSE）

任务执行时，用第二个 PowerShell 窗口订阅事件：

Invoke-RestMethod "http://127.0.0.1:8000/tasks/$taskId/events"

你会看到一串事件：TASK_CREATED → RUN_CLAIMED → RUN_PHASE_ADVANCED → STEP_STARTED → STEP_SUCCEEDED → RUN_SUCCEEDED → TASK_COMPLETED 等。 实时推送用 SSE（第 06 课）：

curl.exe -N "http://127.0.0.1:8000/tasks/$taskId/events/stream"

浏览器打开 WebUI http://127.0.0.1:8000，页面本身也是从这些事件恢复状态的（README.md:246-248）。

6. 读最终答案

Invoke-RestMethod "http://127.0.0.1:8000/tasks/$taskId/answer"

返回的 TaskAnswer（api/models.py:58-76）包含：answer 正文、findings（已过验证门的）、datasets、artifacts、lineage、disclosures（覆盖缺口/数据质量披露）。 再查血缘：

Invoke-RestMethod "http://127.0.0.1:8000/tasks/$taskId/lineage"

你应该能看到 FILE_VERSION → DATASET、STEP → DATASET 这样的边（第 12 课）。

7. 故障演练：验证耐久性

想亲眼看到第 11 课的能力，可以做这个实验：

  1. 创建一个耗时的 Task（prompt 要求「多步分析」）；
  2. 在 Worker 执行中杀进程（stop.bat 或直接关掉窗口）；
  3. 重新 dataharness run；
  4. 观察事件流：RUN_LEASE_RECOVERED 出现，Run 从 checkpoint 继续而不是从头。

这就是「lease 过期 → 原子回收 → 恢复决策 → 续跑」的真实演示（第 11 课）。

8. 故障排查速查

现象检查（README.md:436-478）
dataharness check 失败TOML 格式、路径可写、network_enabled=false
API 能启动但 Task 不执行是否用 dataharness run；status.bat 看 Worker 心跳/沙箱 TCP/digest/Key
沙箱创建失败8080 端口、docker info、digest 一致性、allowed_host_paths、egress 模式
模型调用失败Key 配置、Provider 错误分类（脱敏的稳定分类）

9. 练习：把全流程画成图

练习：总结一张「数据流图」
  1. 在本课操作的基础上，画一张从「curl 建 Project」到「拿到 answer」的时序图，标注每一步经过的层（api → projects/corpus → storage → orchestration → agent → privacy → sandbox → analysis）。
  2. 在图上标出三个「安全边界」：ModelGateway（第 09 课）、OpenSandbox 挂载（第 10 课）、Runtime/Privacy 分离（第 06/09 课）。
  3. 把这张图和你第 01 课的「地图」对比，看看现在能画出多少细节。

小测验：只启动 serve（没有 Worker），创建 Task 后会怎样？

查看解析
API 与 Worker 是独立进程（worker.py:1-6）。Task 入队后由 Worker 循环领取（第 11 课）。所以完整链路要用 dataharness run（启动器同时拉起三个进程，launcher.py:245-339）。

小测验：SSE 事件流的游标是什么？断线后如何补发？

查看解析
api/app.py:268-302：事件 ID 即游标，Last-Event-ID 头或 after 参数都支持；事件事实源是 SQLite 的 events 表（第 06 课），SSE 只是投影。
