配置系统：从 TOML 到 Pydantic Settings

本课解剖 src/dataharness/config.py（169 行）和 dataharness.example.toml：配置怎么声明、怎么校验、怎么保护密钥。

1. 配置文件长什么样

打开 dataharness.example.toml。TOML 是一种简单的键值配置格式：[小节] 分组，键 = 值。本项目的配置结构：

[paths]
runtime_data_root = "runtime-data"      # 数据根目录

[model]                                  # 云模型配置
provider = "deepseek"
model = "deepseek-v4-flash"
api_key = ""                             # 真实密钥只填在 dataharness.local.toml
base_url = "https://api.deepseek.com"

[sandbox]                                # 沙箱配置
endpoint = "http://127.0.0.1:18080"
runtime = "secure-analysis"
network_enabled = false

[extraction]                             # 文件导入限制
max_file_bytes = 104857600               # 100 MiB
supported_formats = ["csv", "parquet", "xlsx", "json", "pdf", "docx", "pptx", "md", "txt"]

[index]                                  # 检索调参
bm25_k1 = 1.2
bm25_b = 0.75
max_snippet_chars = 2000

[budget]                                 # Agent 预算
max_analysis_steps = 50
max_consecutive_failures = 3
max_run_duration_seconds = 3600

[resources]                              # 沙箱资源限制
memory_mb = 1024
disk_mb = 2048
max_processes = 32
max_output_bytes = 10485760
step_timeout_seconds = 300
关键纪律：真实密钥绝不进仓库

这个文件是样例。使用时复制为 dataharness.local.toml（已被 .gitignore 忽略）再填密钥（README.md:87-89）。 模型 Key 只能出现在本地文件里，不得进入 Runtime DB、Workspace、日志或 API 响应（README.md:328-331）。

2. Settings 模型：配置即类型

config.py 用 Pydantic 把配置声明成嵌套模型（config.py:143-154）：

class Settings(BaseModel):
    model_config = ConfigDict(frozen=True)
    paths: PathsConfig = Field(default_factory=PathsConfig)
    model: ModelProviderConfig = Field(default_factory=ModelProviderConfig)
    sandbox: SandboxConfig = Field(default_factory=SandboxConfig)
    extraction: ExtractionConfig = Field(default_factory=ExtractionConfig)
    index: IndexConfig = Field(default_factory=IndexConfig)
    budget: BudgetConfig = Field(default_factory=BudgetConfig)
    resources: ResourceLimitsConfig = Field(default_factory=ResourceLimitsConfig)
  • 七个配置节对应七个 Pydantic 类，一一对应 TOML 的小节。
  • 所有字段都有默认值（如 paths 默认 runtime-data），所以不写配置文件也能启动。
  • frozen=True：配置加载后不可修改，防止运行中悄悄被改。
  • 加载函数用标准库 tomllib 解析（config.py:157-169），不需要额外依赖：
def load_settings(path: Path) -> Settings:
    """从 TOML 文件加载并校验配置。… Raises FileNotFoundError / pydantic.ValidationError"""
    with path.open("rb") as handle:
        data = tomllib.load(handle)
    return Settings.model_validate(data)

TOML 解析成 dict → model_validate 校验并转换为类型安全的 Settings。配置写错类型、写错枚举值，启动时直接报错，而不是运行时才炸。

看 PathsConfig（config.py:19-49）—— 只填一个根目录，其余自动派生：

@model_validator(mode="before")
@classmethod
def _resolve_defaults(cls, data: object) -> object:
    """缺省子根目录时，从 runtime_data_root 派生。"""
    # if projects_root missing -> runtime_data_root/projects
    # if privacy_root  missing -> runtime_data_root/privacy

派生结果（README.md:107-112）：

runtime-data/runtime.db       Runtime SQLite（状态事实源）
runtime-data/privacy/          每 Task 的 Privacy SQLite（PII 映射）
runtime-data/projects/         Project Workspace（文件、索引、产物）

@property runtime_db（config.py:44-48）直接算出 Runtime DB 路径 —— 所有下游组件共享这一个口径。

4. 安全校验：配置层就 fail closed

看 SandboxConfig 的两个关键点（config.py:67-88）：

class SandboxConfig(BaseModel):
    endpoint: str = "http://127.0.0.1:18080"
    runtime: str = "secure-analysis"
    image_digest: str | None = None       # 为空表示"待锁定"，创建沙箱前必须锁定
    network_enabled: bool = False
    api_key: str | None = None            # repr=False，不进入 repr/日志

    @model_validator(mode="after")
    def _reject_network(self) -> SandboxConfig:
        """V1 没有运行期网络开关；即使配置文件显式要求也必须在装配前失败。"""
        if self.network_enabled:
            raise ValueError("V1 Sandbox 不允许启用网络")
  • network_enabled = true 直接启动失败 —— 安全策略在配置加载阶段就强制，而不是等代码运行时才发现。
  • image_digest 默认 None：没有锁定的镜像 digest 就不允许创建沙箱（第 10 课讲 digest 锁定）。
  • api_key 的 repr=False：即使有人打印配置对象，密钥也不会显示出来（config.py:58）。

5. 预算与限制：防失控的第一道闸

两个配置节体现「分层限制」思想（ARCHITECTURE.md:541-551 第 18 节）：

  • [budget]（config.py:120-127）—— DataHarness 自己管的限制：最多 50 个分析步骤、连续失败 3 次熔断、Run 最长 1 小时。
  • [resources]（config.py:130-140）—— 沙箱资源限制：内存 1GB、磁盘 2GB、最多 32 进程、输出 10MB、单步 300 秒。

为什么分两层？因为不同层管不同的失控风险：模型可能疯狂调工具（budget 层管）、生成的代码可能疯狂吃资源（resources 层管）。单靠一层会漏。

6. CLI 怎么用配置

回看 cli.py 的命令（cli.py:44-68）：

dataharness check --config dataharness.local.toml    # 校验配置并打印摘要
dataharness serve --config dataharness.local.toml    # 加载配置并启动 API
dataharness worker --config dataharness.local.toml   # 加载配置并启动 Worker

check 命令打印的摘要刻意不包含任何密钥（cli.py:19-32）：

def _print_settings(settings: Settings) -> None:
    """打印经过校验的配置摘要（不包含任何密钥）。"""

它只显示 api_key_configured: True/False（配置了没有），从不显示值本身。

7. 练习

练习：配置层探索
  1. 复制样例配置：Copy-Item .\dataharness.example.toml .\dataharness.local.toml，然后运行 uv run dataharness check --config .\dataharness.local.toml，观察输出。
  2. 在 dataharness.local.toml 里把 network_enabled 改成 true，再次运行 check —— 看它如何失败（然后改回来）。
  3. 在 config.py 里找到 repr=False 出现的所有位置，想想每处为什么需要。

小测验：config.py 里 SandboxConfig 拒绝网络的方式是？

查看解析
config.py:77-84 的 _reject_network 用 @model_validator(mode="after")，配置一加载就失败。这符合「fail closed」原则：宁可拒绝启动，也不静默降级。

小测验：为什么 api_key 字段要 repr=False？

查看解析
repr() 会出现在调试输出、异常信息、日志里。密钥字段带 repr=False 后，即使有人打印 Settings 对象，显示也是 api_key='**********'（Pydantic 自动打码）。这是纵深防御的一环。
课后主源阅读

Pydantic 校验器文档（model_validator 的 before/after 区别）， 和 TOML 规范（10 分钟看懂格式）。
