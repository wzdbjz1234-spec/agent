FastAPI 入门：逐行读懂 API 层

本课用 src/dataharness/api/app.py（339 行）作为教材，学完你将掌握 FastAPI 的核心概念，并看懂 DataHarness 的全部 30 个 HTTP 路由。

1. FastAPI 的心智模型

FastAPI 只有 5 个核心概念，全部在本项目出现：

概念作用本项目的例子
路由 @app.get("/path")把 URL 绑定到函数app.py:134 的 /healthz
中间件 @app.middleware("http")请求处理前后插入逻辑（如日志、鉴权）app.py:50-86 两个中间件
异常处理器 @app.exception_handler(X)把异常转成统一的 HTTP 响应app.py:88-132 五个处理器
请求模型（Pydantic BaseModel）自动校验请求体/头/查询参数api/models.py 的 CreateProjectRequest 等
依赖注入自动构建函数的依赖参数本项目用应用工厂注入服务（见下）

2. 应用工厂：create_app

整个 API 是一个函数创建的（api/app.py:34-48）：

def create_app(
    services: ApiService | None = None,
    *,
    static_dir: Path | None = None,
) -> FastAPI:
    """创建可注入服务的 FastAPI 实例，并可选挂载同源 WebUI 构建产物。"""
    service = services or build_default_service()
    app = FastAPI(title="DataHarness", version="0.1.0", docs_url="/docs", redoc_url=None)
    app.state.services = service
  • 工厂模式：不创建全局单例 app，而是每次调用生成新实例 —— 测试可以注入假服务（第 13 课会用它跑通验证）。
  • app.state.services：FastAPI 官方推荐的「把业务对象挂到 app 上」的方式，路由里通过 request.app.state.services 取用。
  • docs_url="/docs"：自动生成交互式 API 文档（Swagger UI）。启动服务后打开 http://127.0.0.1:8000/docs 就能看到全部接口并可在线试调。
  • service 就是 ApiService（api/services.py:46-63），一个面向 API 层的业务门面：路由只做「参数校验 + 调用 service + 返回 DTO」，不碰 SQLite/Sandbox/模型 SDK。这叫薄 API（ARCHITECTURE.md:94）。

3. 中间件：每个请求都要经过的关卡

第一个中间件解决一个前端工程问题 —— 浏览器直接刷新前端路由时返回 SPA 页面（api/app.py:50-59）：

@app.middleware("http")
async def serve_spa_navigation(request: Request, call_next):
    """浏览器直接刷新前端路由时返回 SPA shell，同时保留 JSON API 路由优先级。"""
    accepts_html = "text/html" in request.headers.get("accept", "")
    excluded = {"/docs", "/openapi.json", "/healthz", "/readyz", "/diagnostics"}
    if static_index is not None and request.method == "GET" and accepts_html:
        path = request.url.path
        if path not in excluded and not path.startswith("/assets/"):
            return FileResponse(static_index)
    return await call_next(request)

第二个中间件做可观测性（api/app.py:61-86）：记录每个请求的状态码、耗时、错误类型，并且故意不记录请求路径（注释：避免意外携带敏感参数）。这是本项目的安全习惯——「能不记就不记」。

中间件的执行顺序

请求先进入中间件 → await call_next(request) 把请求交给下一个中间件/路由 → 响应返回时继续执行 `call_next` 之后的代码。中间件 1 在最外层，所以它会先收到请求。

4. 异常映射：统一的错误格式

五个异常处理器把「任何可能的错误」折叠成同一个 JSON 结构（api/app.py:88-132）：

{"error": {"code": "NOT_FOUND", "message": "请求的资源不存在"}}
异常HTTP 状态错误码说明
ApiError（业务错误）自定义自定义API 层唯一能"主动抛"的业务错误（api/errors.py:8-14）
RequestValidationError422INVALID_REQUESTPydantic 校验失败
RecordNotFoundError404NOT_FOUND存储层抛的"查无此记录"
ValueError400INVALID_OPERATION状态/边界约束不满足
Exception（兜底）500INTERNAL_ERROR刻意隐藏 SQL/路径/SDK 细节（app.py:126）

顺序很重要：越具体的异常越先注册。兜底的 Exception 处理器保证任何崩溃都返回统一格式，不把内部信息泄露给调用方。

5. 路由解剖：从最简单到最复杂

5.1 健康检查（api/app.py:134-141）

@app.get("/healthz")
async def healthz() -> dict[str, str]:
    return {"status": "ok"}

@app.get("/readyz")
async def readyz() -> dict[str, str]:
    # SqliteRuntimeStore 构造时已完成迁移；这里不读取底层连接，避免健康检查改写业务状态。
    return {"status": "ready"}

约定：/healthz 表示进程活着；/readyz 表示依赖就绪。注意 readyz 故意不做数据库探测 —— 只读探测也可能触发 WAL 写入。

5.2 创建资源（api/app.py:148-150）

@app.post("/projects", status_code=201)
async def create_project(payload: CreateProjectRequest) -> dict[str, object]:
    return service.create_project(payload.name).model_dump(mode="json")
  • payload: CreateProjectRequest —— FastAPI 自动解析请求 JSON、按 Pydantic 模型校验、把错误转成 422。
  • status_code=201 —— 创建成功返回 201。
  • 业务逻辑全在 service.create_project（api/services.py:152 → corpus.create_project(name)）。

5.3 上传文件（api/app.py:186-191）—— 最有意思的路由

@app.post("/projects/{project_id}/files", status_code=201)
async def import_file(
    project_id: str,
    data: Annotated[bytes, Body(media_type="application/octet-stream")],
    x_file_name: Annotated[str, Header(min_length=1, max_length=255)],
) -> dict[str, object]:
    return service.import_file_bytes(project_id, x_file_name, data).model_dump(mode="json")
  • 路径参数 {project_id}、原始字节体 data、请求头 X-File-Name —— 三个来源的参数在一个函数签名里声明，FastAPI 全自动解析校验。
  • 文件名走请求头而不是 multipart 表单 —— 这是官方 REST 惯例（curl 用法见 README.md:280）。
  • body 接收的是原始字节：先落临时文件、验文件名、再走导入管线（api/services.py:197-219，第 07 课详讲）。

5.4 文件内容下载（api/app.py:202-210）

@app.get("/projects/{project_id}/files/{file_id}/versions/{version_id}/content")
async def file_content(
    project_id: str, file_id: str, version_id: str,
    snapshot_id: Annotated[str, Query(min_length=1)],
) -> Response:
    data, media_type = service.read_file(project_id, file_id, version_id, snapshot_id)
    return Response(content=data, media_type=media_type)

注意 snapshot_id 是必填查询参数——文件必须挂在某个 Snapshot 下读取（保证读的是 Run 固定的版本，第 07 课讲 Snapshot 的语义）。

6. ApiService：路由背后的业务门面

ApiService（api/services.py:46-63）把 HTTP 层和基础设施完全隔离。它的构造函数注入：

  • store: SqliteRuntimeStore —— 查询/写状态；
  • corpus: ProjectCorpus —— 项目文件与检索；
  • tasks / runs / sessions —— 三个领域服务；
  • workspace / bridge / verification —— 工作区、发布、验证；
  • observability —— 遥测适配器。

从配置一键装配的方法在 ApiService.from_settings（api/services.py:91-142）—— 这是「组装根」，把 config → SQLite → 服务 → 门面串起来。

7. 你自己加一个路由试试

练习：给 API 加一个统计路由
  1. 在 api/app.py 里仿照 /healthz 加一个路由：GET /api/version，返回 {"name": "dataharness", "version": "0.1.0"}。
  2. 运行 uv run dataharness serve，访问 http://127.0.0.1:8000/api/version 验证。
  3. 再访问一个不存在的路径（如 /nope），观察返回的错误 JSON 格式 —— 是哪一层帮你处理的？
  4. 打开 http://127.0.0.1:8000/docs，找到你的新路由。
